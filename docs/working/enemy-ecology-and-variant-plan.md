# Enemy ecology and variant plan

- Status: working — proposed targets, not implemented behavior or approved canon.
- Owner: Game Director with Narrative, Level Design, Art Director/Animator and QA review; Principal Game Engineer is the sole code writer.
- Recorded: 2026-09-10, after input commit `fb0e5532fe552477f6b28c9fbf2d9e06cfe64341`.
- Scope of this supplement: documentation completeness only; no gameplay implementation, new assets, or new runtime evidence. STOP 1.0b remains pending.

Craig wants more interesting monsters, behaviors and features that belong to each stage, and a world that appears to continue working when the hero is not fighting. The recommended design unit is a recognizable enemy family with a district job or feeding routine, **one changed combat rule**, a visible distinguishing feature, and a consistent tell, recovery and counterplay. A variant is not a palette swap or merely extra health.

Machine workers, creatures and synthetic growth can coexist. Their origin and district fiction below are proposals for Narrative review, not additions to the approved story. Working variant descriptions are production labels; future public names must come from `src/content/identity.ts` once it exists, rather than embedded franchise names.

## Current implementation

The generated catalog contains **12 families**, and `CAMPAIGN_STAGES` contains **10 stages**. Both inventories below use existing internal IDs. Sources: `src/content/enemies/enemy_catalog.generated.json`, `src/enemy/EnemyCatalog.ts`, and `src/content/campaign.ts`.

Existing enemies already have distinct movement classes, preferred engagement ranges, vertical tolerances, attack timing, patrol/alert/chase/retreat states, and spawn windows. Those differences are useful foundations; the named routines, environment responses and signature attacks proposed below are additional work.

Only prerequisites needed by the limited pilot should be built first. Beam/charge dispatch, complex cooperative AI, dynamic terrain and every-family routine are later candidates, not prerequisites for two mine-bot variants.

Local loops should read as **work/feed/perch → notice → alert → combat → return**. Use fixed authored anchors and timing, with a clear return after the hero leaves the leash. A nearby ambient worker or creature may continue an inert routine, but must never disguise a damaging actor as harmless decoration. No simulated economy, offscreen reproduction, global schedules or emergent faction war is required.

Ambient loops need no blocking dialogue or new systemic story flags. Protect breathers, dialogue, checkpoints and first telegraphs. Ambient motion and sound must remain subordinate to an attack's warning; new attacks cannot originate offscreen, through an unreadable overlap, or from the returning work animation. A combatant’s routine adds no attack emissions or attack-hitbox damage; its existing body-contact rule remains visible and consistent. Decorative ambient actors cannot damage the player. Environmental loops that affect collision/damage belong to the approved mechanic system, not cosmetic animation callbacks.

## Limited pilot

Recommend **one family, two biome variants**, using `enemy_mine_bot` in Pyro and Mire. Both stages already place this family, and its implemented crawler/lobbed foundation avoids relying on unimplemented charge/beam support. This is a recommendation pending scope review; the alternative gunner pair proposed by QA is viable but does not align as directly with the Pyro-first stage plan.

Build a **2–3 screens** behavior lab in Phase 2.2 after scope approval, with one safe observation pocket, one isolated encounter per variant and one deliberately simple combination with at most one unchanged supporting family. This lab is not two finished stages. Port the approved Pyro encounter into Phase 2.4, then Mire into Phase 2.5c. No other family expansion before the pair proves the system.

- Pyro slag scavenger: searches a warm slag anchor, retracts its feelers when the local vent arms, then fires one fixed-arc pellet after a proposed 300 ms tell; cool orange shell seam marks at least 350 ms recovery. The vent response uses a bounded mechanic snapshot, not an enemy-owned vent implementation.
- Mire spore forager: searches a filter-growth anchor, retreats toward that patch on alert, then fires one committed lob after a proposed 350 ms abdomen swell; open sac marks at least 400 ms recovery. Retreat distance is bounded to a visible safe pad.
- Preserve the base low-body collider/hurtbox and ordinary Buster contact. A 32px art canvas is not permission to enlarge collision geometry. Shared family identity must survive either presentation.
- One local noncombat routine and one intentional interaction with stage features are enough for each pilot. Do not add partner buffs, procedural nests, status effects or extra attacks to make the trial appear richer.
- The timings above are proposed acceptance targets, not tuned gameplay facts; test at native resolution and adjust once through the existing pilot review with the change recorded.

## Architecture seams

Game.ts must not grow. Pure snapshot-driven behavior belongs under `src/enemy/`, with Phaser physics/sensors at small adapter edges and data under `src/content/enemies/`. The future compiler/marker contract in prompt 02 should carry an optional `variantId`; keep existing `typeKey` behavior compatible for old markers and saves.

- Preserve `typeKey` as the base family identity; use a separate explicit presentation/atlas key. `EnemySpawner.resolveDefinition` and `EnemyEntity.definitionOverride` are the existing integration seam; `context.stageId` supplies a fallback district context only where the new contract explicitly permits it.
- Proposed resolution: establish the legacy base, select the current pilot-or-generated content layer with today's precedence (pilot wins over generated), then apply a validated complete variant preset. Define nested merge semantics explicitly so a partial attack object cannot silently drop timing/projectile fields; do not merge both content layers in a new accidental order.
- Presets use allowlisted behaviors and validated full attack/movement/presentation values, not arbitrary trait bags. Apply family engagement defaults first and the complete variant profile last so exact `typeKey` overrides cannot erase variant intent. Invalid or unknown IDs fail content validation; choose and document a safe runtime fallback for old content at implementation review.
- Add a narrow pure controller called by the existing `EnemyAI.ts` adapter; it consumes immutable actor/hero/terrain/mechanic snapshots and outputs intent plus phase transitions. This does not require replacing the shared AI state machine. Locked facing/aim belongs to attack startup; `EnemyCombat.ts` remains the authoritative attack clock and damage/projectile emitter.
- Add failing checks for lock direction, interruption, pause, exact projectile count, full preset validation and family identity before the mine-bot pilot. Terrain-sensitive retreat requires a `EnemyMotor.ts` world-platform sensor adapter, tested against ledges and walls rather than screen width.
- Route only bounded cosmetic SFX/VFX/footstep events from `EnemyAnimationManifest.ts` through the entity adapter, resetting event deduplication correctly per loop. Animation frame markers must not create a second projectile or damage authority.
- If needed, extend the existing enemy debug/state adapter with `variantId`, `phase`, `lockedAim` and `pendingEvents`. Update automation docs and targeted scripts together; do not expose implementation labels in ordinary player UI.

## Original graphics pipeline

Use the dedicated Art Director/Animator with ChatGPT generation and editing for original concepts, silhouettes, sprite poses and textures, using only approved repository reference paths. Record source/prompt/edit lineage, input/output hashes, licenses, cell sizes and reproducible recipes; never ingest Capcom rips into the public build.

Create genuine editable SVG masters for scalable logos, icons or diagrams where useful. Raster character art remains raster source, not an embedded bitmap called an editable vector. Working sketches do not authorize replacing the hero, bosses or all twelve families.

Extend the existing `scripts/sprites/build-image-prompts.mjs`, `tools/sprites/intake-chatgpt-images.mjs`, `tools/sprites/slice_sheet_to_atlas.py` and `docs/content/sprite-imagegen.md`. Keep source imports, deterministic cleanup/slicing, Phaser atlas validation and any pinned SVG rasterizer reproducible. Required future captures include native **448×252**, enlarged nearest-neighbor and grayscale checks; inspect the actual imported sprite, not only a concept sheet.

One shared family sheet plus targeted variant pose/silhouette edits is the starting production budget. A color change alone fails the brief. Do not claim animation frames, vectors, licenses or runtime readability exist until produced and inspected. Existing style, boss, hero and UI STOPs remain in force.
